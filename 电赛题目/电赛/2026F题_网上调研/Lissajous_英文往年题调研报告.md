## 0. 一句话结论

- **没有发现任何公开的 2026 F 题“视觉闭环断开模式”完整开源方案**；最接近的公开先例是 **2022 年 TI 杯模拟邀请赛 X 题《李萨如图形演示装置》**，但该题是**有线模式、禁用数字信号处理、考模拟锁相环**，与本题“摄像头看屏幕 + 断开后自动闭环”的难度层级完全不同。
- 核心难题（断开后测频测相）在公开文献中**唯一成体系的做法是“拍频/旋转周期法”**：装置输出频率接近未知频率时，李萨如图形会以角速度 ω = m·Δf 缓慢旋转；摄像头测量旋转周期 T 即可反推频率差 Δf = 1/(m·T)。这正是用户“扫频找稳定点 + 微调”的理论依据，文献给出了严格公式和相机实现细节。
- 对用户基线最有价值的两条可落地改进：
  1. **用“归一化亮区面积曲线”替代四边波峰计数**（IIETA 论文方法）——MicroPython 单帧只数阈值化像素总数，计算量远低于 find_blobs 边缘计数，抗网格线干扰强；
  2. **用椭圆拟合（ellipse fit）同时测幅度比和相位**——光学测量文献中椭圆拟合测相可达 1e-4 rad 量级（理想条件），比“x 截距读相位”更稳。
- “100Hz 步进 × 991 频点 vs 10s”这个矛盾，**未检索到任何公开帖子/论文直接讨论**（如实报告“未找到”）；从旋转拍频原理推算，粗扫只能靠“包络形状（1:1 椭圆包络 vs 2:1 ∞包络）”做宽容差粗分类，最后几 kHz→几 Hz 的逼近仍只能靠“图形是否稳定”这一二元信号逐步走——这是本题的物理本质难点，用户现方案的 192 点扫频思路方向正确，问题在 K230 单帧判稳准确率（41.1%）而非策略本身。

## 3. 核心难题专项：断开信号源后如何得知输入频率与相位

### 3.1 公开做法归类（a/b/c/d 四类）

**(a) 纯视觉测频测相 —— 已查证的主流做法 = 拍频/旋转周期法**

- **E1（IIETA 2023，已精读）**：相机拍屏视频，灰度二值化，逐帧算归一化亮区面积 NA(i)；当 f_Y = (m/n)f_X + Δf 时图形以周期 T = 1/(m·Δf) 旋转，NA 曲线出现负峰；峰间距即 T，最小二乘融合多周期 → Δf_X = 1/(mT)，f_测 = (m/n)f_X + 1/(nT)。
  - 精度结论（原文）：精度与视频帧率成正比；作者自评当前旋转周期估计精度“还不够高”。**换算到本题**：相机 30fps、观察窗 T_obs≈0.5s → 可分辨的最小频差 ≈ 1/(m·T_obs) ≈ 2Hz（m=1）。即“接近锁定后”，视觉闭环能把频率修到 ±2Hz 量级——远好于题目 100Hz 步进隐含的要求（题目只要求图形稳定，并不要求装置读出频率数值）。
- **相位测量**：一旦频率锁定（图形静止），椭圆即定常曲线。**E7** 椭圆拟合法：对屏幕上二值化轨迹做最小二乘椭圆拟合，得长短轴 a/b → 相位 φ = arcsin(√(1−(b/a)²)) 量级（圆 = a/b=1、φ=90°；对角线 = b=0、φ=0°）；光学测量文献中理想条件相位误差 1e-4 rad（【一方说法】）。这比用户“双相位 37°确认”类启发式更成体系，且单帧可算。
- **切点法（C4）**：仅在严格整数比下成立；断开模式下 DDS 不可能精确命中频点，图形持续旋转，切点数逐帧跳变——**这就是用户 K230 四边波峰计数准确率 41.1% 的根本原因，不是代码问题，是方法选错了观测变量**。

**(b) 示波器数据接口（USB/网口读测量值）—— 技术上成立，合规存疑**

- E10（scopebench-mcp，开源）+ E11（Tektronix OpenChoice）+ R&S RsInstrument + Siglent SigScopeLab 均证明：现代数字示波器通过 USB/LAN 直接读取频率/幅度测量值是工程上的成熟操作。
- **合规判断**：题目说明“测试允许挡板遮挡示波器屏幕外部分、关闭测量信息窗口”，并强制“摄像头拍示波器屏幕”——这组说明的意图就是**封闭视觉通道、禁止任何数据链路**。接裁判示波器的数据口几乎必然违规（且装置无法预知示波器型号/驱动）。结论：**技术可行、默认不可行，仅作为“需向组委会确认”记录**，不建议作为方案。

**(c) 锁相/扫频类方案**

- 用户现有方案（DDS 扫频找图形稳定点 + 旋转方向微调）本质就是**视觉辅助的锁频环（visual PLL）**，与 E1 原理完全一致，方向正确。
- C1（2022 TI 杯 X 题）证明：若装置**仍连着输入信号**，正解是硬件 CD4046 锁相环直接倍频——但本题要求 5 明确切断电气连接，硬件 PLL 无参考可用，只能退回视觉 PLL。
- 未检索到“最大似然频率估计用于示波器 XY 图”的公开实践；E2（事件相机频闪检测）思路可类比但硬件不符。

**(d) “100Hz 步进 991 频点 vs 10s”矛盾的公开讨论**

- **如实报告：未找到。** 以“李萨如图形显示控制装置 摄像头 自动模式”“李萨如 旋转 拍频 视觉锁定”等多组中英文关键词检索，未发现任何论坛帖/博客/论文直接讨论该时间预算矛盾。2026 年 8 月省赛刚结束（见 C5 获奖新闻），经验贴尚未沉淀。

| 改进点 | 依据 | 对用户基线的提升 | 可落地性 |

| 1. 把 K230 观测变量从“四边波峰计数”换成 E1 的“归一化亮区面积 + 帧间相关性” | E1【已查证】 | MicroPython 里只需 `img.binary()` 后统计 ROI 内像素总数（可分 8×8 子块），单帧开销远低于 find_blobs；面积曲线负峰/周期即图形旋转周期 → **直接输出带符号频差（旋转方向=频差正负）**，省掉“双相位 37°确认+第二探测点交叉确认”的试探逻辑 | 高：改动集中在 K230 端一个函数 |
| 2. 单帧做椭圆拟合替代“波峰门（左==右、上==下）”判圆/判∞ | E7【一方说法，摘要级】 | 椭圆长短轴比直接给 φ 和等幅度判据（圆：a/b≈1；对角线：b≈0；∞：2:1 包络），比严格相等门更抗噪；K230 MicroPython 可实现简化版（质心+主轴方向，或离线 PC 原型已有 OpenCV Chamfer 匹配，可移植） | 中：MicroPython 最小二乘需手撸 5×5 线性方程，但只有 5 个未知数 |
| 3. 粗扫策略：先按“包络形状”宽容差分类（1:1 椭圆包络 vs 2:1 ∞包络），再在包络命中后进入旋转速率精锁 | E1/E8/E9 原理【已查证/一方说法】 | 包络形状在 Δf 几百 Hz 时仍可分辨（图形旋转快 → 帧内积分成对应包络），粗扫步长可放到 1~2kHz（50~100 点 × ~20ms ≈ 1~2s），把 192 点预算省给精锁阶段 | 高：与现有扫频框架兼容 |
| 4. 精锁阶段用“旋转角速度反馈”替代“逐点 100Hz 步进试” | E1 公式 Δf=1/(mT)【已查证】 | 由连续两帧的图形主轴角（椭圆拟合可得）求角速度，直接比例修正 DDS 频率——视觉 PLL 闭环，避免盲走；5s HOLD 期内可连续修正独立晶振漂移 | 高 |
| 5. （不推荐）接示波器 USB/LAN 读值 | E10/E11【一方说法】 | 技术上一行 SCPI 搞定，但与题目“挡板遮屏外、强制摄像头”的封闭性设计冲突，默认违规 | 低：合规风险 |

**综合判断**：公开文献支持用户的总体路线（视觉 PLL + DDS），但指出其**单点故障在 K230 的观测算法（四边波峰计数），而非系统架构**。最值得立即验证的是改进点 1+4：用“帧间图形相关性/面积曲线”得到带符号频差，把 192 点盲扫变成“粗扫包络 + 旋转速率闭环”，预期可同时缓解“41.1% 准确率”和“10s 预算紧”两个已知痛点。
